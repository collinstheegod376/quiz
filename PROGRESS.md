- **Sentinel Security Hardening (Migration 07)** — Live breach confirmed and sealed:
  - **SEC-01 PATCHED — Credential Exposure**: Live audit confirmed anon clients could `SELECT password_hash` from `user_profiles` using the public key, returning plaintext passwords in cleartext. Fixed via PostgreSQL column-level `REVOKE SELECT ON user_profiles FROM anon/authenticated` and `GRANT SELECT (id, username, avatar_url, ...)` on safe columns only.
  - **SEC-02 PATCHED — Auth Bypass via `'VERIFIED'` Token**: `update_own_profile_fn` and `delete_own_account_fn` accepted `p_current_password = 'VERIFIED'` as a magic bypass, allowing anyone to hijack or delete any account without knowing their password. Replaced with server-side `pgcrypto.crypt()` verification in all RPCs — no bypass strings exist anywhere.
  - **SEC-AUTH PATCHED — Server-Side Password Hashing**: Removed `bcryptjs` client-side hashing entirely. All password operations (login, register, update, delete) now run inside `SECURITY DEFINER` PostgreSQL functions (`login_fn`, `register_fn`, `update_own_profile_fn`, `delete_own_account_fn`) using `pgcrypto` `gen_salt('bf', 10)` + `crypt()`. Passwords are verified inside the DB and the hash **never leaves Postgres**.
  - **SEC-05 PATCHED — Stat Inflation Caps**: `increment_user_stat_fn` now enforces per-call amount maximums (e.g. `total_score` capped at 1600 per call, all binary stats at 1) preventing scripted score inflation.
  - **SettingsModal Updated**: Profile update and account deletion now require the user's current password, validated server-side. Delete confirmation UI includes a password confirmation field.
  - **VoiceContext Type Fix**: Resolved pre-existing `isQuestionAutoMuted` type mismatch in `VoiceContext.tsx` provider value object.
